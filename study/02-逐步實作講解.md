# amr_forklift 逐步實作講解（Windows 11 ＋ WSL Ubuntu 24.04 ＋ ROS 2 Jazzy）

> 這份是 [01-新手完整導讀](01-新手完整導讀.md) 的實作篇。每一步都寫了「要做什麼 → 指令 → 你應該看到什麼 → 為什麼」，
> 而且**「應該看到什麼」全部是 2026-11-06 在這台 PC 實際跑出來的結果**（記錄在 `run-logs/`）。

## 步驟 0：先搞懂這台電腦跟原作者的差別

| 項目 | 原作者 | 這台 PC |
| --- | --- | --- |
| 作業系統 | Ubuntu 22.04 | Windows 11 裡的 WSL Ubuntu 24.04 |
| ROS 2 | Humble | **Jazzy** |
| 模擬器 | Gazebo Classic 11 | **Gazebo Harmonic（gz sim 8.15）** |
| 顯示 | 實體顯卡 | WSLg 軟體繪圖（llvmpipe）→ 模擬速度約真實時間的 28% |

**為什麼重要**：Ubuntu 24.04 根本裝不了 Gazebo Classic，所以作者的 `gazebo.launch.py` 和
`gazebo_plugins.xacro` 在這裡不能直接用。我們**不改作者原檔**，另外加 6 個「Jazzy 專用檔」（步驟 4）。

```bash
# Windows 端（閱讀用）

# WSL 端（執行用，ROS 工作區的 src 底下）
```

**小坑**：使用者給的網址是 `amr_forklif`（少一個 t），GitHub 回 `Repository not found`。

**為什麼要放在 `~/amr_ws/src`**：ROS 2 的工作區慣例是「工作區根目錄／src／各套件」，
`colcon build` 會掃描 `src` 底下所有含 `package.xml` 的資料夾。

## 步驟 4：加入 Jazzy／Gazebo Harmonic 移植檔

新檔都在 Windows 的 `study/jazzy/`，複製到 WSL 套件對應的資料夾：

| 新檔 | 取代作者的 | 做什麼 |
| --- | --- | --- |
| `models/nebula_urdf/gz_plugins.xacro` | `gazebo_plugins.xacro` | 新版差速驅動、gpu_lidar 雷射、IMU、關節狀態外掛 |
| `models/nebula_urdf/model_gz.xacro` | （新入口） | include 作者的 `model.xacro`＋上面的新外掛 |
| `worlds/nebula_arena_gz.world` | `nebula_arena.world` | 同一個場地，多加 5 個新版必要系統外掛 |
| `launch/gz_sim.launch.py` | `gazebo.launch.py` | 開 gz sim、放機器人、**ros_gz_bridge 轉接 9 個 topic** |
| `launch/slam_nav_gz.launch.py` | `slam_nav.launch.py` | SLAM Toolbox＋Nav2（改用下面的參數檔） |
| `config/navigation_jazzy.yaml` | `navigation.yaml` | 以 Jazzy 官方參數為底，套上這台車的尺寸與速度 |

```bash
S=/mnt/c/Users/USER/workspace/amr_forklift/study/jazzy   # 依你的使用者名稱調整
D=~/amr_ws/src/amr_forklift
cp $S/models/nebula_urdf/*.xacro $D/models/nebula_urdf/
cp $S/worlds/*.world $D/worlds/
cp $S/launch/*.py $D/launch/
cp $S/config/*.yaml $D/config/
cd ~/amr_ws && colcon build --packages-select amr_forklift --symlink-install
```

**移植的三個觀念**（新手最需要懂的）：

1. **新版 Gazebo 不會自己發 ROS topic**。外掛只發「Gazebo 自己的 topic」，要靠 `ros_gz_bridge` 一條條轉成 ROS topic。
   橋接寫法 `/scan@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan`：`[` 代表 Gazebo→ROS，`]` 代表 ROS→Gazebo（例如 `/cmd_vel`）。
2. **固定關節會被合併**。URDF 轉成 Gazebo 格式時，用 fixed 接起來的零件（雷射、IMU）會被併進 `base_footprint`，
   所以感測器要加 `<gz_frame_id>lidar_link</gz_frame_id>`，資料的座標系名稱才會對。
3. **Jazzy 的 Nav2 多了新節點**（route_server、docking_server、collision_monitor…），用 Humble 的舊參數檔會缺設定而啟動失敗，
   所以改「拿官方預設檔、只改機器人相關的值」。

## 步驟 6：⚠️ 這台 WSL 特有的坑——ROS 節點互相看不到

**症狀**：節點明明在跑，`ros2 node list` 卻什麼都沒有；`ros2 topic pub --once` 一直卡住不結束。

**診斷**：用最簡單的官方範例測

```bash
ros2 run demo_nodes_cpp talker &           # 另一個程序發 "Hello World"
ros2 topic echo /chatter --once            # 結果：topic does not appear to be published yet
```

**解法**：換通訊層（RMW）

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
ros2 topic echo /chatter --once            # 結果：data: 'Hello World: 11'  ✅
```

**為什麼**：ROS 2 底層用 DDS 這種網路協定讓節點互相「發現」對方。Jazzy 預設的 FastDDS 在這台 WSL 的網路環境下探索失敗，
換成 CycloneDDS 就正常。**以下每個終端機都要先執行 `export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`**，
可以寫進 `~/.bashrc` 一勞永逸。

### 7-1 觸發緊急停止 → 🐛 發現作者程式碼的 bug

另開終端機：

```bash
ros2 topic pub -r 5 -t 10 /safety_hazard std_msgs/msg/Bool "{data: true}"
```

**實際看到**：

```
[ WARN] CheckSafety: Safety hazard check failed! ACTIVE HAZARD DETECTED!
AttributeError: 'Logger' object has no attribute 'critical'
[ros2run]: Process exited with failure 1
```

**節點直接當掉**。原因在 `amr_behavior_tree.py` 的 `EStopAction.update()`：

```python
self.logger.critical("EMERGENCY ESTOP: Halting AGV motors!")   # ← py_trees 的 Logger 沒有 critical
```

py_trees 的 Logger 只有 `debug / info / warning / error` 四個等級。
這行在「發布停車指令」**之前**就爆了，所以真正遇到危險時，機器人**不但沒停，控制程式還整個結束**——
這是安全功能最不該出現的錯。（它只在危險時才會執行到，平常巡邏完全不會發現，這就是為什麼要「刻意觸發每個分支」做測試。）

**修正**（一個字）：`critical` → `error`。修正檔在 `study/jazzy/patches/estop-logger-fix.patch`。

```bash
cd ~/amr_ws/src/amr_forklift
sed -i "s/self.logger.critical(/self.logger.error(/" amr_forklift/amr_behavior_tree.py
cd ~/amr_ws && colcon build --packages-select amr_forklift --symlink-install   # 一定要重編！
```

> 💡 **為什麼改完要重編**：`CMakeLists.txt` 用 `install(PROGRAMS ... RENAME ...)` 把 `.py` **複製並改名**到安裝目錄，
> 不是捷徑連結。所以就算加了 `--symlink-install`，改原始碼後也要重新 `colcon build`。實測沒重編時錯誤照舊。

### 7-2 修正後重測三個分支

```bash
ros2 topic pub -r 5 -t 10 /safety_hazard std_msgs/msg/Bool "{data: true}"
ros2 topic echo /cmd_vel --once          # linear.x: 0.0 ✅ 停車
ros2 topic pub -r 5 -t 10 /safety_hazard std_msgs/msg/Bool "{data: false}"
ros2 topic pub -r 5 -t 3  /battery_voltage std_msgs/msg/Float32 "{data: 10.5}"
```

**實測輸出**：

```
[ WARN] CheckSafety: ACTIVE HAZARD DETECTED!
[ERROR] EStopAction: EMERGENCY ESTOP: Halting AGV motors!     ← 每 0.2 秒重複
[ WARN] CheckBattery: Battery voltage critical: 10.5V (Threshold <= 11.0V)
[ INFO] BatteryChargingAction: Charging... Battery Voltage: 11.0V
[ INFO] BatteryChargingAction: Charging... Battery Voltage: 11.5V
[ INFO] BatteryChargingAction: Charging... Battery Voltage: 12.0V
...每秒 +0.5V，到 14.2V 回到巡邏
```

**看懂了什麼**：Selector 的「優先順序」——有危險時根本不會去問電池；危險解除後才輪到電池；電池充飽才輪到巡邏。

## 步驟 9：看雷射資料，親眼確認 scan_filter_node 在工作

寫一小段 Python 同時訂閱 `/scan` 與 `/scan_filtered`，印出正前方 ±20° 的距離：

```
原始 /scan     正前方±20度: 0.42 0.41 0.42 | 1.17 1.16 1.15 1.17 1.14 1.16 1.17 1.18 | 0.41 0.42 0.41
過濾 /scan_filtered        : inf  inf  inf  | 1.17 1.16 1.15 1.17 1.14 1.16 1.17 1.18 | inf  inf  inf
```

**解讀**：

- 中間的 1.15 公尺＝正前方的牆
- 兩側的 **0.41 公尺＝機器人自己的叉架柱子**（在約 ±16° 的方向）
- 過濾後柱子變成 `inf`（無限遠）→ 導航不會把自己的身體當成障礙物

這就是 README 工程挑戰第 6 點的實證。另外也知道了：**出生點在場地角落，前方 1.15 m、右方 1.9 m 是牆，後方 8.7 m、左方 5.2 m 是空地**。

## 步驟 11：送導航目標（第一次失敗，也是學習）

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.2, y: 0.0}, orientation: {w: 1.0}}}}"
```

**實測**：`error_code: 204`、`Goal finished with status: ABORTED`

**為什麼**：204 是「目標在地圖範圍外」。SLAM 的地圖原點就是機器人起點、x 軸＝機器人正前方。
前方 1.15 m 就是牆，地圖只畫到 x=1.17，目標 1.2 剛好超出。

**改成後退偏左的空地**：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: -3.0, y: 1.0}, orientation: {w: 1.0}}}}"
```

**實測**：

```
Goal accepted
error_code: 0
Goal finished with status: SUCCEEDED      ← 耗時 39 秒
終點 TF map→base_footprint: (-2.883, 1.006)  ← 誤差約 12 公分，在允許的 0.25 m 內
```

背後發生的事：`bt_navigator`（Nav2 自己的行為樹）→ `planner_server` 用全域代價地圖算出路線 →
`controller_server`（Jazzy 預設 MPPI 控制器，速度上限 0.26 m/s）每秒 20 次算速度 → `/cmd_vel` → 橋接 → Gazebo 轉輪子。
